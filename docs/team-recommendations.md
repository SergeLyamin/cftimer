# Организация работы

Для пилота нужен владелец продукта, доступ к тренерам и один ответственный за интеграцию кода. AI-агенты выполняют ограниченные независимые задачи; штат из пяти специалистов и прежние зарплатные оценки не обоснованы текущим объёмом.

Владелец выбирает пользовательское поведение и участвует в испытаниях зала. Основной агент ведёт OpenSpec, код, интеграцию и проверки. Дополнительным агентам отдавать конкретные независимые области: аудит, исследование, ревью протокола или отдельный модуль с заранее заданными границами файлов. Не назначать двум агентам один файл. Сначала общий контракт, затем параллельная работа; итоговое ревью обязательно.

Чтобы экономить токены: давать агенту вопрос, нужные пути, формат результата и критерий готовности; не поручать каждому читать весь архив; переиспользовать аудит и актуальные specs. В новой сессии читать README → config → текущий change. Архив открывать только по конкретной причине.

[Прежние рекомендации](../archive/documentation-before-sdd/docs/team-recommendations.md) сохранены как история и больше не задают бюджет или состав команды.
