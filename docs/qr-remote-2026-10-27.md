# QR remote — desktop-кандидат 27.10.2026

Версия `0.2.0-dev.0`, ветка `feat/qr-remote-control`. Работа изолирована в `/private/tmp/cf-timer-qr-20261027`; база обновлена до `44dadcb` с отчётом о публикации 0.1.5. Production и исходный рабочий каталог не изменялись. Это локальный кандидат для UI-приёмки, не готовый релиз или пилот.

## Запуск и просмотр

```sh
npm ci
npm run build
npm run preview:qr
```

Desktop: http://127.0.0.1:43970/; локальный relay: `127.0.0.1:43980`. Для разработки: `npm run dev:qr`. Настройки перечислены в `.env.example`. QR этого localhost-preview не предназначен для подключения физического телефона: такой тест требует отдельного доступного устройствами HTTPS/WSS окружения.

Владелец проверяет расположение и сворачивание QR, настройку тренировки, читаемость пульта, запуск/паузу/перезапуск/редактирование, подтверждение выхода в меню и отдельное отключение пульта. Одобрение UI владельцем пока не получено.

## Реализация и принятые результаты

- Ядро таймера отделено от React и сети. `DisplayRuntime` владеет состоянием, revision и атомарным выполнением намерений при одном замере времени.
- Общий строгий протокол описывает команды, снимки и ответы. Экран остаётся единственным источником состояния и времени; relay управляет комнатами и полномочиями.
- Сервер выдаёт отдельные секреты экрана и пульта. Поколения соединений и монотонный `controlEpoch` исключают прежнего владельца; новое право становится готовым только после подтверждения экраном.
- Повторная доставка не исполняет команду повторно. ID связан с эпохами и номером команды; проверяются revision и срок действия. Потеря ACK даёт честное «результат неизвестен», восстановление запрашивает результат без автоматического повторения действия.
- Обработаны отдельные интервалы: 20 секунд на согласие живого пульта и 60 секунд без связи перед освобождением управления. Потерянный fence ACK повторяется с ограниченной частотой.
- Маршрут `/remote` создаёт пульт до React, обычный вход — локальный таймер. Новое приглашение в открытой вкладке обрабатывается заново; секрет из fragment удаляется. Отзыв/ошибка приглашения очищают старые данные восстановления.
- Настроены проверки Origin, размеров и схем сообщений, частоты запросов и ограничение ресурсов. Технические журналы ограничены и не включают credentials. Полная продуктовая диагностика ещё не реализована.

Руководитель интегрировал результаты инженеров application/transport, relay и UI, устранил замечания на границах протокола. Независимый UI/UX-эксперт принял desktop-кандидат после исправлений; это не заменяет одобрение владельца.

## Что остаётся

OpenSpec: закрыты 10 из 28 задач. Незакрытые пункты могут содержать работающую реализацию, но остаются открытыми до всех предусмотренных ими проверок.

1. Получить явное desktop UI approval владельца; исправления интерфейса проходят повторный desktop review.
2. После одобрения — расширенные проверки мобильных размеров, браузеров, reload/storage, несовместимых версий, PWA/offline и регрессии. Дополнить проверки TTL, лимитов и гонок передачи прав.
3. Завершить privacy-safe session diagnostics: ограниченная очередь событий, отчёты и trace по SSH, retention и проверки редактирования секретов.
4. Пройти HTTPS/WSS staging: два зала, несколько устройств, потеря связи, перезапуск relay, измерение рассинхронизации и успешности pairing. Проверить QR с 1–3 м и вибрацию на физических устройствах.
5. Отдельно подготовить развёртывание и получить разрешение на публикацию. Архивировать/sync change можно только после реализации и проверки требований.

Основание остановки перед расширенными проверками — [AGENTS.md](../AGENTS.md), staged UI review: сначала доступ владельцу к desktop и его явное одобрение. Разрешение на публикацию 0.1.5 не распространяется на QR-релиз.

## Исправление доступа с телефона после первого просмотра

Владелец сообщил, что Safari/Firefox не открывают QR. Причина окружения: preview слушал только loopback, а QR наследовал `127.0.0.1` из адреса открытого экрана. На телефоне этот адрес не ведёт к компьютеру.

Для повторного просмотра на одной Wi-Fi сети preview запущен на LAN-адресе компьютера. Пример для текущего адреса (при смене сети адрес нужно определить заново):

```sh
CF_TIMER_DEV_HOST=10.10.10.48 CF_TIMER_ORIGINS=http://10.10.10.48:43970 npm run preview:qr
```

На компьютере нужно открыть именно `http://10.10.10.48:43970/`, затем сканировать новый QR. Relay остаётся на loopback и доступен через proxy. Это временный локальный HTTP preview; production по-прежнему требует HTTPS/WSS и отдельного разрешения.

Также устранена следующая потенциальная ошибка LAN HTTP: генерация claimSecret/ID больше не зависит от `crypto.randomUUID`, требующего secure context. Общий helper использует 16 криптографически случайных байт `crypto.getRandomValues`, без небезопасного fallback. Typecheck и browser/relay build прошли; `/healthz` через LAN отвечает 200. Владелец подтвердил, что подключение с физического телефона заработало. Это подтверждение доступа, а не завершённая UI-приёмка или полный аппаратный тест. Схема участников и обмена сообщениями добавлена в [архитектуру](architecture.md#подключение-qr-пульта).

## Повторный UI review: QR в шапке и статус пульта

По замечаниям владельца после успешного подключения телефона уточнён интерфейс:

- QR открывается компактной кнопкой в шапке слева от настроек; на главной, настройке и таймере панель по умолчанию закрыта.
- Зелёный огонёк QR-кнопки означает подключённый действующий пульт при доступном relay.
- Пульт использует шапку «Пульт» со статусом и точкой по [remote-flow-v1](../design/concepts/2026-10-22-remote-flow-v1.png). Ожидание и отключение отличаются от готовности словами и цветом.
- Технический номер/метка экрана убирается из пользовательского интерфейса. Протокол и полномочия от этого не меняются.
- Мягкий нейтральный radial-фон пульта сохраняется по пожеланию владельца.

Это новая итерация desktop UI: окончательное одобрение владельца и расширенные проверки пока открыты.

Результат этой итерации: typecheck и browser/relay build прошли; независимый UI/UX-эксперт принял desktop 1440×1000. Проверены QR перед настройками на home/setup/timer, default closed, открытие/закрытие, Escape и возврат фокуса, отсутствие случайной паузы по Space в панели. Подключение первого пульта даёт зелёный статус, ожидание второго — жёлтый с причиной, release — серый; технических номеров нет, radial-фон сохранён. Окно LAN оставлено на главной с открытым свободным QR.

Свидетельства: [главная с QR](../output/playwright/qr-header-home.png), [пульт подключён](../output/playwright/qr-header-connected.png), [ожидание передачи](../output/playwright/qr-header-waiting.png). В OpenSpec теперь закрыты 11 из 29 задач (добавлена и проверена отдельная UI-правка 4.7). Явное одобрение этой версии владельцем ещё ожидается.
