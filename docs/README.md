## Где истина

| Источник | Назначение |
| --- | --- |
| [openspec/specs](../openspec/specs/) | Действующие контракты. Сейчас есть только workflow проекта; runtime ещё не синхронизирован в baseline до завершения приёмки |
| [openspec/changes](../openspec/changes/) | Предлагаемое поведение, дизайн решений и невыполненные задачи |
| `docs/` | Объяснения, исследования, вопросы и эксплуатационный план; не вторая копия требований |
| [archive](../archive/README.md) | Исторический код и документы; их утверждения нельзя принимать за факт реализации |
| [design](../design/) | Исходные визуальные референсы; изменения трактовки описаны в UX |

При конфликте сначала установить статус: подтверждённый факт кода, принятое требование или гипотеза. Будущую функцию не записывать в baseline как реализованную. Успешный OpenSpec validate проверяет формат документов, а не приложение.

## Что изменено в прежней документации

README больше не обещает отсутствующие `npm start`/deploy/www. Architecture явно разделяет AS-IS и предложение. Project plan заменён этапами с критериями выхода. Technical requirements указывают на OpenSpec вместо дублирования. Team recommendations описывают работу владельца и агентов вместо неподтверждённого найма команды за десятки тысяч долларов. Исходные документы сохранены без правки в архиве.

Текущая реализация: [приёмка](implementation-2026-10-22.md), [правки дизайна и проверка 23.10](ui-refinement-2026-10-23.md), [взаимодействие и удержание экрана 26.10](ui-refinement-2026-10-26.md), [инструкция](user-guide.md), [ресурсы и лицензия](assets.md). Baseline runtime пока не синхронизирован: change открыт до завершения приёмки.
