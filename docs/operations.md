# Сессии, журналы и диагностика без кабинета

Статус: проект требований, код ещё не реализован. Пользователь подтвердил отсутствие серверной базы аккаунтов/программ; хранить можно временные сессии и журналы. SSH-доступ владельца сервера заменяет отдельный web admin UI, но сервер всё равно проверяет техническое право пульта на конкретный экран.

## Где живут данные

| Данные | Где | Срок/поведение |
| --- | --- | --- |
| Активный таймер | Память страницы компьютера | Reload создаёт idle и новую сессию; active snapshot не восстанавливается |
| Последние параметры, cache приложения | Браузер | Локально, без обязательной отправки серверу |
| Сессии экранов, приглашения, право пульта | RAM relay | TTL и уборка; рестарт relay требует переподключения, но локальное время продолжается |
| Диагностические/продуктовые события | JSON stdout → journald/container logs | Предложение: 14 дней и общий лимит 1 GiB, уточнить под VPS |
| Яндекс Метрика / Google Analytics | Внешние системы после настройки владельцем | Не влияют на запуск/таймер; секреты и приватные pairing URLs туда не передаются |

## Что дополняет обычную аналитику страниц

`display_session_started`, `workout_started`, `workout_paused`, `workout_resumed`, `workout_finished`, `workout_reset`, `pair_requested`, `controller_acquired`, `transfer_requested`, `transfer_approved`, `transfer_denied`, `transfer_expired`, `controller_disconnected`, `controller_reconnected`, `controller_replaced`, `command_ack_timeout`, `protocol_rejected`.

Событие содержит schemaVersion, eventId, eventTime, receivedAt, appVersion, случайный несекретный correlation ID (не токен доступа), deviceKind screen/remote, отдельный actionSource local/remote, несекретный workoutId, sessionEpoch/controlEpoch, mode, outcome/reasonCode и latency при наличии. Не писать полный payload команды, QR URL, секрет пульта, постоянный device fingerprint или введённый пользователем текст. IP из proxy/access logs не использовать как идентификатор человека; отдельно настроить маскирование/retention инфраструктурных журналов.

События с клиента валидируются, ограничиваются по размеру/частоте; клиентские тайминги и пользовательские eventTime не считаются доверенным источником безопасности. Серверное решение о выдаче/отказе доступа логирует сервер. Продуктовые события локальной тренировки отправляет экран.

## Offline и честность отчётов

Без сети relay не узнает о завершении локального таймера. Предлагается bounded очередь диагностических событий в браузере: максимум 200 событий, TTL 24 часа, eventId для дедупликации. Отправка при восстановлении связи; полученное поздно отмечается. Ошибка записи/отправки или отсутствие аналитики не останавливает таймер. После сброса страницы журнал событий может дослаться, но **не восстанавливает таймер и права**. Секреты в очередь не попадают.

Без доставленных событий отчёт помечает сессию incomplete, не называет её успешной или аварийной автоматически. Дедупликация повторной доставки делается по eventId в отчёте/ingest. Не писать каждую секунду отсчёта — это шум и расход диска.

## Планируемые инструменты в tools/

Ниже проект CLI, команды ещё не существуют:

- `tools/report-usage.mjs`: сводка за период — сессии, запуски по режимам, источник управления, completion с долей неполных данных, pairing time, передачи/отказы, ACK p50/p95.
- `tools/trace-session.mjs`: последовательность событий одного несекретного correlation ID, причины разрывов/замены, версия клиента.

Они читают JSONL export/stdin и работают по SSH. Без web-панели, пользовательской авторизации, базы аккаунтов и нового публичного admin endpoint. Доступ ограничивается существующими OS/SSH permissions. Точный `journalctl -u <service>`/Docker путь определяется deployment change. [systemd journalctl](https://www.freedesktop.org/software/systemd/man/latest/journalctl.html).

## Как проверять

Завершить локальную и remote-тренировку, передать/отклонить пульт, отключить WAN, вернуть связь, перезагрузить телефон/экран. Отчёт должен различить эти случаи, не посчитать повторную доставку дважды, не содержать секретов и явно показать missing telemetry. Количество сессий не равно количеству людей: браузер без аккаунта не даёт достоверного «кто именно».

Технические источники: [OWASP logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html), [MDN WebSocket](https://developer.mozilla.org/en-US/docs/Web/API/WebSockets_API/Writing_WebSocket_client_applications), [MDN onLine limitations](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/onLine).

## Конфиденциальность перед включением сбора

[BL-02 и проект политики](privacy-policy-draft.md) требуют инвентаризации не только application events, но и access/error logs прокси, хостинга, CDN, cookies и browser storage. Несекретный session ID не доказывает анонимность. Сроки 14 дней/1 GiB и очередь 200/24 ч — предложения до проверки реализации и оснований обработки. Метрика/GA подключаются отдельным шагом после определения юрисдикции, состава данных и выполнения применимых требований; отказ от аналитики не блокирует таймер или пульт. Не передавать внешним счётчикам credentials, QR URL и идентификаторы управления.
