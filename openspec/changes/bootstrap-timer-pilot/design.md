# Design

## Context

Мотивация — [proposal](proposal.md). На момент предложения runtime отсутствовал; прежние TS/JS версии сохранены в archive. Подтверждены PC+TV, пилот 1–3 зала и продолжение занятия при потере интернета. Макеты просмотрены; анализ и предлагаемые поправки — [UX](../../../docs/ux.md).

## Goals / Non-Goals

**Goals:** чистое тестируемое ядро, независимость отсчёта от UI и сети, читаемый экран, воспроизводимая сборка и подготовленный offline cache.

**Non-Goals:** network remote, account backend, универсальный редактор занятий, все браузеры телевизоров, гарантия звука/точности во время sleep ОС.

## Decisions

1. **TypeScript + React + Vite, Tailwind 4.** React обслуживает UI, ядро не знает о React. Vanilla TS возможен, но для будущих экрана/пульта увеличивает ручное управление DOM. SSR/Next не дают пользы таймерному экрану. Node 24 LTS — target; exact compatible versions выбираются и закрепляются на первом bootstrap commit. Совместимость Tailwind и источники — [architecture](../../../docs/architecture.md).
2. **Папки по ответственности:** `src/timer/` для конфигурации/переходов/проекции времени, `src/ui/` для экрана и настройки, `src/platform/` для audio/storage/fullscreen/offline. Не возвращать иерархию BaseTimer/множества событий без нужды.
3. **Одна программа как последовательность фаз.** Конфигурация компилируется в подготовку, работу и отдых. Пресеты только заполняют конфигурацию. В первой версии нет кругов/вложенных комплексов. Работа 1–6039 с, отдых 0–6039, подготовка 0–30, раунды 1–99, суммарно ≤4 ч. Предел работы/отдыха 99:99 подтверждён владельцем; подготовка 0–30 с и общий лимит сохраняются.
4. **Время через Clock interface.** Reducer обрабатывает explicit actions; текущий interval считается из elapsed. performance.now в пределах документа; requestAnimationFrame/timeout только обновляют view. Delay test перескакивает сразу к актуальной фазе. У timestamp есть один владелец: display runtime. Пауза сохраняет накопленное elapsed; resume задаёт новый anchor. Системные часы не изменяют длительность.
5. **Сигналы из переходов.** Идентификаторы phase/transition исключают повтор звука при rerender; финал приоритетнее сигнала смены. Assets загружаются перед готовностью. Возврат из фона пропускает устаревшие сигналы. Обычный foreground target — 250 мс за час при заданных условиях, не обещание real-time ОС.
6. **Storage только для настроек.** По подтверждённому решению reload/повторное открытие компьютера означает новую idle сессию. Не сохранять active snapshot для восстановления. Последние параметры сохраняются локально с версией схемы и безопасным fallback; аналитическая очередь не является состоянием таймера. Reload телефона-пульта обрабатывается remote change и никогда не сбрасывает компьютер. Для самостоятельного мобильного таймера предлагается такое же локальное правило idle после reload.
7. **PWA progressive enhancement.** Service worker кэширует shell, шрифты и звуки по versioned manifest; offline-ready только после успешной подготовки. Новая версия ждёт idle/completed и подтверждения; API/будущие auth routes не кэшируются. Проверка обновления охватывает все открытые clients; неответившая вкладка блокирует активацию. Не использовать unconditional skipWaiting/clients.claim и не удалять cache активной версии; безопасный fallback — закрытие всех вкладок между занятиями. Конкретный поддерживаемый PWA plugin/Workbox dependency выбрать при bootstrap по официальным docs; hand-written сложный caching framework не нужен.
8. **Локальная проверка готовности.** Audio unlock и fullscreen вызываются локально на устройстве с таймером; Wake Lock проверяется feature detection и запрашивается best effort при старте. Пока удержание требуется, видимая страница восстанавливает его после visibility return или освобождения; повторные попытки ограничены. Отказ/отсутствие API даёт явный fallback без остановки таймера или бесконечных запросов. Browser suspension и сон компьютера не входят в обещания пилота.

9. **Самостоятельный мобильный UI.** Обычный вход на смартфоне создаёт локальный таймер без QR/remote controls; явный pairing route принадлежит следующему change. На больших экранах — обычный display layout. Предлагаемый initial compact criterion: меньшая сторона viewport <768 CSS px; проверить на устройствах. Rotation/resize не меняют владельца времени или сессию. Владелец выбрал всегда A: только выбор режима. Карточка последней тренировки B не используется.
10. **Уточнённая форма и ввод после 0.1.2.** Интервалы в одной колонке: раунды/работа/отдых/свёрнутая «Подготовка»/«Старт»/«Общее время: XX:XX», без разделительной линии/лишних пояснений итога/звука в форме; у поля подготовки скрыта повторная видимая подпись, ARIA сохранено, отступ к summary сокращён. Работа/отдых принимают ММ:СС с парами 00–99 до 99:99; seconds = min×60+sec, максимум 6039, подготовка остаётся 0–30 с, total ≤4 ч. Четыре цифровые позиции, пятая набранная цифра игнорируется без NaN/потери preview; oversized numeric paste ограничивается 99:99, явные сегменты >99 отдельно ограничиваются 99, раунды >99 ограничиваются 99. Уведомление об ограничении живёт примерно 10 с с fade. Сохраняются середина/выделение/Backspace/очистка; incomplete/non-numeric блокируют старт. Верхняя граница round-trip поля 6039→99:99; основной readout нормализует в 100:39. Колесо/click-pair-select остаются BL-12/13.
11. **Общие настройки с мягким завершением.** Шестерёнка перед fullscreen на всех экранах заменяет динамик и i. Диалог содержит звук с проверочным сигналом при включении, эффекты с кратким демо при включении, краткую подсказку клавиш; отдельной кнопки проверки звука нет. Внизу фактическая версия сборки и только «GitHub автора» на репозиторий в отдельной вкладке, без текста авторства/старого About. Звук default false, краевые эффекты и отдельная опция confetti true; локальное сохранение с безопасным fallback в память при отказе/повреждении. Системный reduced motion отключает эффекты независимо от настройки. Юридический draft не публикуется как действующая политика; BL-02 остаётся открыт.
12. **Композиция и навигация 0.1.2.** В настройке/таймере единая верхняя строка: стрелка в тонкой круглой окантовке слева, название, служебные кнопки; на таймере интервальной модели название дополнено N из M (на подготовке 1 из M), For Time — заданным лимитом; нет отдельной надписи «Настройка», дублирующего h1 или нижней стрелки. Бренд-шапка таймера скрыта. Выход из активного занятия подтверждённый, без результата; completed возвращается в меню сразу. Пауза/продолжение — неподвижный icon-only круг 56×56; сброс 40×40 со stop-иконкой выдвигается справа, редактирование 40×40 с карандашом — слева, только на paused без сдвига основного круга. Между центральной кнопкой и каждой боковой — 28 px. Редактирование открывает параметры текущей программы, сбрасывая старый paused runtime; новый отсчёт начинается только по «Старт». Сброс немедленно запускает ту же конфигурацию с подготовкой без подтверждения и фокусирует новую паузу. Размеры pause/resume 56×56 и боковых действий 40×40 CSS px — уточнение владельца 27.10.2026. Кнопки нейтральные с белой рамкой/красным hover и видимым focus; локальной early finish нет.
13. **Клавиатура и диалоги.** Space pause/resume, Escape только на paused перезапускает, F fullscreen. Пропуск при редактировании, модификаторах и repeat; Space не перехватывает интерактивные элементы. Открытый диалог получает Escape первым; Escape выхода из fullscreen не сбрасывает таймер. Настройки и подтверждение меню привязаны к триггеру, ограничены visual viewport по ширине/высоте, допускают внутреннюю прокрутку. Нейтральный ×/backdrop/Escape закрывают настройки, Tab остаётся внутри, фокус восстанавливается. В подтверждении отмена — button со ссылочным оформлением. Диалоги не останавливают отсчёт; подтверждение сброса удалено. При включении звука проигрывается один проверочный сигнал; при включении пульсации/конфетти — конечное демо без изменения snapshot. Закрытие настроек и выключение эффекта прекращают демо, системный reduced motion имеет приоритет.
14. **Типографика, цвет и мягкий эффект.** Локальный Oswald и фиксированные ячейки цифр/разделителя сохраняют геометрию; видимые двоеточия крупного времени скрыты, ширина прежних ячеек сохранена, доступное имя по-прежнему содержит обычное время с двоеточиями; основные цифры белые. Палитра названия фазы, полосы и края едина: подготовка #F2A541, работа #EF4A40, отдых #59B8E8. Край красный последние 10 с каждой работы (вся работа короче 10 с), голубой первые 20% отдыха; 2-секундный цикл, низкая непрозрачность, blur ≤100 px с уменьшением на небольшом viewport. Эффект только при running, видимой странице и включённой опции; отсутствует на paused/completed/hidden/off/reduced motion. Локальные шрифты и CF favicon SVG/ICO входят в offline cache.
15. **Две шкалы вместо tiles.** Первая полоса прямоугольная, высота 50 CSS px, radius 0: только текущая фаза preparation/work/rest, countdown remaining/duration 1→0, рабочий For Time elapsed/duration 0→1; paused frozen, конечная доля по направлению. Вторая полоса 3 px: сегменты work/rest пропорциональны длительности, без prep/последнего rest, EMOM work-only. Сегменты прямоугольные без рамок, фон как у первой полосы, заполнение red work/blue rest. Countdown показывает remaining 1→0, начиная с хронологически первого сегмента у крайнего правого края, и опустошается справа налево: row-reverse при data-direction=down, fill origin слева. Count-up располагает первый сегмент слева и показывает elapsed 0→1 слева направо. Номерные tiles удалены, раунд вынесен в заголовок. На подготовке countdown timeline полностью цветной; после завершения обе полосы скрываются вместе с интерактивными поверхностями, а конечные доли остаются только внутренним расчётом. Нижние действия не перекрывают шкалы.
16. **Мягкое завершение.** Собственная локальная реализация confetti без CDN, [визуальный референс](https://codepen.io/georgehastings/pen/pVOevW). Независимая persistent опция по умолчанию true. One-shot только при естественном completed/лимите, не при menu exit/reset/manual finish или rerender. Частицы падают, оседают внизу и остаются статичными до выхода/повтора/выключения, без непрерывного RAF после оседания; off/reduced motion без анимации. Результат показывает «ТЫ МОЛОДЕЦ! 🏆» вместо «ГОТОВО», отдельное состояние лимита For Time сохраняет смысл. Не перекрывать результат/кнопки, не останавливать и не сбрасывать ядро.
17. **Поэтапная приёмка.** Сначала локальная реализация и минимальные проверки запуска/оценки desktop. Затем владелец смотрит desktop; до явного UI approval не запускать оставшуюся мобильную/адаптивную, cross-browser, regression/offline/PWA и полную проверку. Публикация требует успешных проверок и отдельного явного разрешения; для 0.1.3 оно получено последним сообщением владельца, прежний релиз сам по себе не авторизует новый.
18. **Уведомления в настройках.** Статусы/инструкции Wake Lock и offline readiness, ручной retry/repair находятся в уведомлениях настроек; постоянные строки/кнопки на home/timer убраны, таймер и cache lifecycle не меняются.
19. **Управление через readout.** Цифры, phase bar и workout timeline — три отдельные native-button поверхности. Клик/Enter/Space исполняют один toggle running↔paused, completed не меняют, при открытом диалоге не перехватывают управление. Краткое ARIA-имя действия/состояния не обновляется каждую секунду вместе со snapshot; роль/текст времени и прогресса сохраняют доступное чтение без шумного live announcement. Не вкладывать интерактивные кнопки друг в друга и не допускать второй паузы от глобального Space.


## Risks / Trade-offs

- Reload компьютера намеренно прерывает занятие → документировать сброс; обновление PWA не должно автоматически делать reload.
- Разные браузеры ограничивают звук/сон → реальный тест PC/iPhone/Android, инструкция для зала; самостоятельный мобильный таймер проверяется уже на локальном этапе; пульт — на следующем.
- PWA cache удалён браузером → offline-ready вычислять по фактическим assets, не по одному флагу в localStorage.
- Старые шрифты/звуки могут иметь неясное происхождение → проверить источник или заменить перед распространением.
- Предлагаемые режимы/границы/последний отдых не подтверждены тренерами → вопрос о примерах программ в docs/questions; спецификация обозначена как proposal, правки до apply.

## Migration Plan

Создать реализацию в активном src, архив не изменять. Сначала чистый build и один работающий отсчёт, затем остальные режимы, UI, audio и offline. Проверить сценарии и production preview. Не переключать live-домен. Откат на этом этапе — предыдущий проверенный commit/артефакт новой реализации, а не запуск архивного сервера. Только после верификации sync/archive этого change; затем remote.

## AMRAP paint hardening — 0.1.4

Владелец сообщил о серой полосе при AMRAP 09:36 и разрешил выпуск после проверок. Исходный дефект не воспроизведён в чистых Chromium/Firefox/WebKit, конкретный браузер владельца пока не указан. Защитная переделка: полоса не сжимается во flex, meter/fill абсолютно привязаны к границам 50 px; доля задаётся шириной вместо scaleX, прозрачная click-кнопка имеет appearance none. Математика/фазы/направления не меняются. Browser regression проверяет реальную площадь, цвет и hit-test на 09:36, а не только aria-valuenow/transform. Нельзя выдавать эту проверку за подтверждение исходной причины или физического устройства владельца.


## Desktop refinement — 2026-10-27

Focus полей следует смыслу: раунды белые, работа красная #EF4A40, отдых голубой #59B8E8, подготовка оранжевая #F2A541; error остаётся отдельным состоянием. Сначала проверить desktop и передать владельцу локальную версию; до его UI approval не запускать расширенную приёмку. Production остаётся 0.1.4, разрешение следующего выпуска не получено.
