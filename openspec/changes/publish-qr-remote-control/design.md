# Design

## Context

Владелец явно разрешил публикацию после ручной UI-приёмки. Production0.1.5 — статический сайт, www→releases/d7734a5; SSH-ключ доступен толькоdevelop7, timer и Nginxvhost недоступны. СистемныйNode18.19.0 не соответствует target24. На публичных /ws,/healthz,/remote сейчас404. Это блокирующие ограничения, не основание публиковать неработающийQR.

## Goals / Non-Goals

**Goals:** проверенный0.2.0, один приватный relay, TLS на существующем Nginx, изоляция залов, осмысленные IP budgets, атомарный статический выпуск и откат.

**Non-Goals:** новые аккаунты, Redis/кластер, публичная админка, включение внешней аналитики, объявление завершённого аппаратного пилота или полной продуктовой диагностики.

## Decisions

1. Browserdist и приватный relay пакуются отдельно с SHA256. Relay содержит закреплённый ws8.22.0; source tree/archive/env не попадают в www. Отдельный remote/index.html позволяет текущему статическому хостингу открыть pairing route без глобального SPA fallback.
2. Node24.22.1linux-x64 из nodejs.org с проверкой официальногоSHA256 устанавливается отдельно от системногоNode, не затрагивая другие сервисы. Для локального runtime-check используется та же версия darwin-arm64.
3. Выделенный systemdservice cf-timer-relay отtimer, bind127.0.0.1:43980, exactOriginhttps://timer.lyamin.org, bounded memory/lograte, restart-on-failure. Установка системной unit требует администратора; действующий PM2daemon других задач не меняется.
4. Только Nginx /ws направляется в loopback с Upgrade, /healthz — минимальная проверка; Apacheproxy не требуется. XFF перезаписывается$remote_addr. Backend доверяет одиночному валидномуIP только отloopback и только по opt-in, иначе использует socketIP. Это предотвращает обход лимитов непроверенной цепочкой.
5. Проверки проходят до переключения. Администратор сначала тестирует Nginxconfiguration и servicehealth; WSS/protocol smoke обязателен. Переключение www не выполняется без действующего relay. Прежний0.1.5, relayrelease и hash-assets сохраняются.

## Risks / Trade-offs

- Нет доступаtimer/администратора: подготовить полный локальный пакет и точный handoff; production оставить на0.1.5, не заявлять успех.
- Перезапускrelay теряет ephemeral rooms: экран продолжает локальный timer, пульт переподключается через новый fencing/snapshot.
- HTML/SW имеют старые max-age30days: администратор меняет revalidation в существующих locations, не подменяя неизвестныйvhost; установленныйSW обновляется отдельно без прерывания занятия.
- WebKit runner среды может быть неработоспособен: отдельно записать недоступный инструмент, не выдавать его за успешную Safari-приёмку.
- Журналы только технические allowlisted, без секретов/IP в app log. Полные продуктовые события/retentionCLI остаются в исходномremotechange; их нельзя объявлять реализованными.
