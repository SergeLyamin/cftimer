# Proposal

## Why

Главный сценарий продукта — любой пользователь управляет большим экраном с телефона. Старый сервер из архива имел один общий host и не подходит для нескольких залов; нужна новая модель комнат и доступа.

## What Changes

- Добавить Node/WSS relay, изолированную комнату и полномочия host на каждый экран.
- Дать крупный сворачиваемый QR с ограниченным сроком; первый пульт подключается свободно, второй запрашивает передачу у текущего.
- Создать отдельный mobile UI пульта по явному приглашению (обычный вход на смартфоне остаётся личным таймером), один активный controller, передача по согласию или после 60 секунд без связи, понятные статусы.
- Ввести единый прикладной runtime для локальных/удалённых действий, атомарный start(config), явные отказы, display ACK, дедупликацию, revision/epoch, срок исполнения и reconnect через snapshot плюс запрос результата без проигрывания старых команд.
- Согласовать пульт с локальным UI: pause/resume, restart/edit на паузе, подтверждённый returnToMenu и repeat после результата; отдельного finish/configure в публичном протоколе нет.
- Ограничить ресурсы relay и согласовывать версию протокола до выдачи управления.
- Сохранять автономную работу экрана при пропаже сервера/сети/телефона.
- Различать reload компьютера (сброс сессии/таймера) и телефона (переподключение).
- Добавить ограниченные структурированные события и CLI-диагностику по SSH; сервер хранит только сессии и журналы. Опциональная вибрация — progressive enhancement пульта.
- Ручной код/ссылка и трансляция экрана перенесены в BL-06/07 после QR-пилота.
- Не включать аккаунты, платежи, LAN offline remote, Smart TV, синхронные несколько экранов и кабинеты залов.

## Capabilities

### New Capabilities
- `remote-control`: pairing, передача права, комнаты, команды, reconnect, мобильный пульт и диагностика сессий.

### Modified Capabilities
Нет. Действия применяются через публичный контракт timer-operation, добавляемый bootstrap-timer-pilot; его семантика времени не меняется.

## Impact

**Зависимость:** локальный runtime bootstrap реализован; UI кандидата 0.1.5 одобрен и программно проверен 27.10.2026. Владелец разрешил начать QR в изолированной ветке параллельно выпуску локальной версии; аппаратная приёмка остаётся условием пилота, а не объявляется выполненной. Эта работа не даёт разрешения публикации QR. Добавляются server/shared protocol и controller/display UI, интеграционные и E2E тесты. Экран остаётся источником истины состояния. HTTPS-инфраструктура и rollout под реальный домен оформляются отдельно после выбора сервера.
