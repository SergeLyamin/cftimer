# Design

## Context

См. [proposal](proposal.md). Зависит от завершённого bootstrap-timer-pilot. Требуется несколько независимых залов; архивный глобальный host запрещён архитектурой. Пилот с облачным интернетом, но локальный отсчёт переживает потерю relay.

## Goals / Non-Goals

**Goals:** отдельные room/host/controller полномочия, deterministic command handling, заметная недоступность remote, восстановление из snapshot без остановки дисплея.

**Non-Goals:** distributed consensus, несколько writer, shared auth/accounts, база тренировок, LAN transport, соревнования с синхронизацией нескольких экранов.

## Decisions

1. **Один Node процесс + ws.** Комнаты in-memory; API создания/приглашения и WebSocket messages валидируются общей строгой схемой. Redis/горизонтальное масштабирование не требуется для пилота; добавление реплик без общей модели состояния запрещено. Конкретный HTTP framework вторичен.
2. **Display authoritative.** Server owns authorization/room epoch; display owns timer state/revision. Только display исполняет actions и выдаёт ACK результата. Control revision увеличивается при принятой команде/автоматическом переходе фазы, не при каждом UI tick. Снимки также имеют возрастающий snapshot sequence для порядка внутри одной revision и epoch.
3. **Технические credentials без аккаунтов.** Room ID не даёт права host. Случайный host secret (≥128 бит) живёт в памяти документа компьютера. QR связывает с одной display session; приглашение обновляется после использования/120 с. Secret во fragment очищается из URL сразу после чтения. Первый претендент при свободном пульте получает credential автоматически, без локального approval/PIN. Общий acquisition path для первого подключения, accept, takeover после 60 с и explicit release: сервер резервирует одного кандидата, повышает controlEpoch, экран подтверждает fencing, лишь затем новый пульт получает статус ready. При недоступном экране кандидат остаётся waiting/no display, не становится готовым управляющим. QR разрешает запрос доступа, не постоянное управление.
4. **Передача между пультами.** У владельца один pending requestId на 20 с. Accept/refuse поступают только от действующего controller. При accept сервер сериализует передачу, увеличивает controlEpoch, сообщает экрану; выдача новому пульту подтверждается после того, как экран принял новую controlEpoch и fenced старую. Delayed команды старого поколения отклоняет также экран. Запоздалое accept, duplicate и конкурирующие запросы не могут создать двух writer. Refuse/timeout при живом владельце не выдаёт доступ. 20 с ограничивают только approval request, не отдельное ожидание освобождения: если владелец пропал, связанный претендент может оставаться на экране ожидания до lastContact+60. При возврате владельца прежний истёкший requestId не оживает: нужен новый запрос. «Отменить запрос» отменяет также ожидание acquisition. Истечение QR после валидного связывания не обрывает ожидание; токен ожидания не даёт права командовать. Предложение anti-spam: один pending request и не более одного нового запроса от претендента за 30 с.
5. **60 секунд без связи.** Server-side lastContact обновляется подтверждённым heartbeat текущего пульта; grace считается от него, а не от обнаружения разрыва. После 60 с новый претендент может получить пульт через тот же acquisition path с display ACK, без согласия прежнего владельца. Если старый вернулся раньше выдачи новому, может восстановить credential; гонку решает один server event loop. Если другой уже получил право, старый видит replaced и не переигрывает offline actions. Explicit «Отключить пульт» освобождает право сразу. Блокировка телефона сама по себе не означает уход, если связь остаётся живой.
6. **Команды и ordering.** versioned envelope: protocolVersion, roomId, sessionEpoch, controlEpoch, commandId, expectedRevision, type, payload. Display сериализует local/remote actions; stale отклоняются с snapshot. Dedup кэш bounded на весь lifetime сессии для принятых IDs либо эквивалентный watermark; лимит должен не разрешать повтор старого действия после вытеснения. Explicit configure/start/pause/resume/finish/reset, без toggle. Configure допускается только в idle, finish завершает активную программу после подтверждения. Проверка dedup предшествует expectedRevision, чтобы потерянный ACK не превратился в повтор действия.
7. **Delivery states.** Remote показывает pending → accepted/rejected/unknown. Через 3 с без display ACK — unknown, не failure/success. Повтор доставки того же намерения использует прежний commandId. После reconnect сначала snapshot и выяснение результата неизвестной команды; никаких offline queues. Server receipt не является display ACK.
8. **Clock projection.** Snapshot несёт phase, elapsed/remaining, status, revision, sequence, timing sample. Phone оценивает отображаемое время по clock-offset/RTT handshake и монотонным часам локально; сырые performance.now разных устройств не сравниваются. Мобильное время приблизительно; authoritative display только на PC. Начальный acceptance target p95 расхождения ≤250 мс при RTT≤100 мс, два устройства в foreground; отдельно от цели локального timer-core.
9. **Disconnect/cleanup.** Heartbeat detects missing peer ≤10 с; экспоненциальный backoff с jitter и максимумом 10 с. Host disconnected 10 мин → cleanup room. Сессия max 8 ч; relay restart → new epoch, новый pairing, местный таймер не сбрасывается. При room expiry host UI объясняет необходимость нового соединения, сохраняя программу.
10. **Abuse controls.** WSS/HTTPS, same-origin allowlist, 16 KiB frame limit, pairing 5/min per source плюс глобальный budget и лимит запросов на экран. Команды ≤10/sec/controller с небольшим burst; превышение отклоняется. Не логировать secrets/QR; Referrer-Policy no-referrer на pairing/controller; auth/session API не кэшировать service worker. Origin не заменяет token authorization.
11. **Один transport host.** Каждое успешное возобновление привязано к server-side connection generation, прежний transport fenced и не публикует state/ACK. Host credentials живут в памяти текущего документа; новая вкладка/reload создаёт новую комнату и не наследует host через localStorage/sessionStorage. Компьютерный reload создаёт новый idle runtime/room без восстановления active snapshot. Credential пульта допустим в sessionStorage вкладки телефона для reload; recovery не выдаёт новые права и всегда проверяет current controlEpoch. У нового документа телефона без действующего credential — обычный запрос доступа. Копия вкладки не создаёт второго writer: у credential одно актуальное поколение socket. При закрытии экрана old room закрывается best effort и перестаёт отвечать; при reload новый документ создаёт новую sessionEpoch. Таймер старого закрытого документа не переносится.

12. **Журналы вместо кабинета.** JSON stdout с server timestamp, eventId, несекретным correlation ID, mode/source/outcome/reason/latency. Клиентские события валидировать/rate limit; серверные решения логировать на сервере. Bounded local queue 200 событий/24 ч для offline usage — предложение; дедуп eventId в report. Retention предложение 14 дней/1 GiB. tools/report-usage.mjs и tools/trace-session.mjs читают export/stdin по SSH, публичных admin endpoints нет. Источники и поля — [operations](../../../docs/operations.md). Метрика/Google — отдельные необязательные adapters после определения оператором юрисдикции/потоков данных, выполнения применимых требований и предоставления ID; BL-02 описывает подготовку политики.
13. **Haptics.** Опционально после user gesture, visible page и подтверждённой команды; feature detection плюс тест пользователем. Не обещать iPhone/Safari или background alarm; отсутствие физического отклика не ошибка таймера.

14. **Вход и QR visibility.** Только явный pairing route открывает пульт; обычный адрес смартфона открывает личный таймер из bootstrap. Resize не меняет роль. На большом экране QR можно свернуть до «Пульт», локально сохраняя предпочтение. Сворачивание не отзывает credential и не отменяет связанное ожидание; при раскрытии показывается действующее приглашение или no connection. Ручной ввод кода/ссылки и casting вне этого change (BL-06/07); прежние PNG с кодом — reference, не обязательство реализации.

## Risks / Trade-offs

- Публичный QR позволяет любому получить свободный пульт → это подтверждённая модель продукта; активный владелец защищён запросом передачи и rate limit.
- Блокировка телефона может привести к 60 секундам без heartbeat → уведомить о возможности передачи; не обещать распознавание физического ухода.
- In-memory state исчезает при рестарте → осознанно повторный pairing; тренировка не прерывается. Персистентные комнаты позже.
- Сеть может задержать или повторить команду → epoch/revision/dedup и ACK от экрана; пользователь видит unknown, не ложный успех.
- Два конфликтующих действия требуют повторного намерения → это предпочтительнее неожиданного reset/паузы; показать актуальное состояние.
- Cloud relay не работает без WAN → локальный экран работает; LAN mode отдельный продуктовый объём.

## Migration Plan

После принятия локального таймера реализовать протокол, rooms, tests, display integration, затем mobile UI. Тестировать два зала и реальные WSS через staging proxy. Deployment change выбирает host/domain/rollback. При откате remote экран не должен терять локальный mode; архивный общий server.js не используется. До полного прохождения сценариев этот change остаётся открытым.
