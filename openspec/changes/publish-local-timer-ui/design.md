# Design

## Context

Мотивация — [proposal](proposal.md). Домен уже раздаёт статический релиз 4ef225e через www symlink; детали прошлого выпуска — docs/deployment.md. Runtime интерфейса 23.10 зафиксирован в 082c009 и проверен в docs/ui-refinement-2026-10-23.md. Для повторного выпуска 26.10 runtime зафиксирован в f325d81, предыдущий активный релиз — 082c009; процедура и ограничения прежние. Первоначальная попытка ключа отклонена; владелец предоставил пароль пользователя timer. Секрет не сохраняется в проекте.

## Goals / Non-Goals

**Goals:** проверяемый артефакт, отдельный каталог релиза, атомарное переключение, сохранение старых hash-assets, HTTPS/browser smoke и фактический отчёт.

**Non-Goals:** изменения приложения, установка Node на сервере, настройка relay, DNS, перезапуск Nginx/Apache/PM2 и завершение аппаратной приёмки.

## Decisions

1. Собрать dist локально из зафиксированного runtime. Передать архив с SHA256, а не исходники/node_modules/archive. Это использует уже подтверждённый статический хостинг и не требует изменения сервисов.
2. Создать releases/<commit> и проверить каждый файл по SHA256. До переключения сохранить фактический путь www и предыдущие hash-assets в новой assets, не заменяя новые файлы.
3. Переключить www временным symlink и атомарным mv в пределах одного каталога. Предыдущий релиз не удалять. Откат использует тот же приём с прежним путём.
4. Использовать отдельную SSH control session для пароля, не помещать пароль в shell-команды, файлы и репозиторий; закрыть сессию после работы.
5. Проверить свежий браузер и браузер с предыдущим установленным SW. При необходимости использовать принудительную revalidation запроса регистрации, но не skipWaiting, reload активной тренировки или очистку пользовательского кэша.

## Risks / Trade-offs

- У sw.js ранее был max-age 2592000 → повторно записать реальные заголовки, проверить обновление с существующей версией. Исправление Nginx требует администратора и в эту операционную публикацию не входит.
- Нет SSH-аутентификации → не переключать сайт; продолжать независимые build/push, отразить блокировку.
- Старые вкладки запрашивают прежние assets → сохранить hash-assets в новом каталоге и прежний каталог целиком.
- Публичный smoke не заменяет PC+TV/телефоны → оставить bootstrap приёмку открытой.

## Migration Plan

Проверить текущий www; загрузить и сверить отдельный релиз; сохранить предыдущие assets; атомарно переключить; проверить HTTPS/assets/шрифт/SW и browser smoke. При неуспехе новой версии вернуть прежний symlink и записать причину. После успеха записать commit, путь, SHA256 и результаты, затем push документации.
